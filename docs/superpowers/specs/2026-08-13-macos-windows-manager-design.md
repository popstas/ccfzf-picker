# macos-windows-manager: окна мака в списке сессий

## Problem

Про открытые окна терминалов в этой связке рассказывает ровно одна машина —
Windows. Её трекер (`claude-wt` в windows11-manager) кладёт на remote-host файл
`~/.ccfzf.sessions.claude-wt.json`, агрегатор `ccfzf --state` его читает и
добавляет каждой сессии поле `window`, а всему ответу — `windowHost` и
`windowPid`.

Мак в этой картине слеп. Сессии он открывает — прямо сейчас на нём живут
три окна kitty, и каждое это `ssh -t remote-host exec $SHELL -ic '… claude
--resume <id>'`, запущенный пикером, — но ни одно из них ни в чьём списке не
значится. Отсюда три следствия, и все три человек видит:

- Чекбокс **`only windowed`** в пикере на маке фильтрует в пустоту: поле
  `window` есть только у сессий с окнами на Windows.
- Пометки **▣** у сессий, открытых с мака, нет вовсе.
- **Enter поднять окно на маке не может.** Он и не пытается: `canFocus`
  сверяет единственный верхний `windowHost` со своим конфигом, и на маке это
  поле оставлено пустым намеренно — «фокуса не бывает».

Второе, помельче, но из того же корня: у агрегатора **один** источник окон, и
второй трекер в нынешнюю схему не помещается ни на каких условиях.

## Solution

Новый репозиторий **`macos-windows-manager`** — Tauri 2, трей без окна,
оконный трекер на маке. Делает он только claude-wt-часть: следит за окнами
терминалов, привязывает их к сессиям и публикует список на remote-host.

Агрегатор учится читать **каталог** файлов трекеров вместо одного файла и
сливать их, приписывая каждой записи окна её машину. Пикер перестаёт судить о
хосте по верхнему полю и судит построчно.

Работа разбита на три этапа; спроектирован здесь **только первый**.

| Этап | Что даёт человеку |
|---|---|
| **1. Окна мака видны** | ▣ у своих сессий, рабочий `only windowed`, правдивый список |
| **2. Enter поднимает окно** | Подъём окна вместо второго процесса на том же транскрипте |
| **3. Снимки и расстановка** | Геометрия окон, снимки раскладки, восстановление |

Порядок не переставляется: этап 2 бессмыслен без правды в списке, этап 3 — без
привязки окон к сессиям.

## Архитектура этапа 1

Четыре места, и границы между ними те же, что у Windows-ветки.

### Приложение на маке

Tauri 2, **только трей — окна нет вовсе**, в отличие от пикера. В меню:
состояние трекера, «Grant Accessibility…», Start/Stop, Quit.

Внутри — поток трекера с тактом в секунду:

| Модуль | Роль |
|---|---|
| `windows.rs` | Перечисление окон через Accessibility |
| `tracker.rs` | Стабилизация заголовка, привязка к сессии, слоты |
| `sessions.rs` | Индекс «заголовок → сессия» из дампа на remote-host |
| `publish.rs` | Файл окон, отпечаток, доставка по ssh |

**Перечисление.** Для каждого приложения из списка терминалов —
`AXUIElementCreateApplication(pid)` → `AXWindows` → `AXTitle`. Список задаётся
bundle id: `net.kovidgoyal.kitty` (умолчание), `com.mitchellh.ghostty`,
`com.googlecode.iterm2`. Отдельно берётся `AXFocusedWindow` фронтового
приложения — из него считается `focusedAt`.

**Тождество окна между тактами** держится сравнением `AXUIElementRef` через
`CFEqual`, а не частным `_AXUIElementGetWindow`. Так можно потому, что **в
публикуемом файле идентификатора окна нет вовсе**: `read_windows` в агрегаторе
берёт из записи только `title`, `desktop`, `lastSeen`, `focusedAt`.
Идентификатор нужен трекеру и никому больше — значит и хватит любого, стабильного
в пределах его жизни.

**Привязка** повторяет `tracker-helpers.js` из windows11-manager: заголовок
считается устоявшимся после двух тактов подряд (вход в сессию перещёлкивает
заголовок два-три раза — шелл, claude, имя сессии), слот помнит привязку и
список заголовков, двойники по заголовку разводятся так же.

**Индекс сессий** тянется по ssh из `~/.ccfzf.sessions.json` на remote-host,
кэш 15 секунд, обновление — только когда попался незнакомый заголовок. На каждом
такте за ним не ходят: заголовок меняется на каждый ответ агента, а дамп и так
отстаёт.

**Разрешение нужно одно — Accessibility.** `CGWindowListCopyWindowInfo` с
macOS 10.15 отдаёт `kCGWindowName` только при разрешении Screen Recording, а
подъём окна (этап 2) без Accessibility невозможен вовсе. Брать заголовки оттуда
же, откуда потом брать подъём, — это одно разрешение вместо двух.

### Формат и доставка

На remote-host появляется каталог `~/.ccfzf/windows/`, в нём `<host>.json` того
же формата, что нынешний одиночный файл: `generated`, `host`, `pid`, `windows`,
`snapshots`, `projects`.

Разницы с Windows-файлом три:

- `desktop` у каждой записи — `null`. Программного интерфейса к Spaces у macOS
  нет, и подменять его нечем.
- `snapshots` и `projects` пусты: это этап 3 и Windows-сторона соответственно.
- Появляется верхнее поле `focus` — **умеет ли этот трекер поднимать окно**.
  Мак в этапе 1 объявляет `false`, на этапе 2 оно станет `true`. Windows-файл
  этого поля не знает, и его отсутствие читается как `true`: там подъём работает
  и работал всегда.

Доставка — одним `ssh` с мультиплексированием (`ControlMaster`), запись через
временный файл и `rename` в том же каталоге: читатель опрашивает раз в секунду,
и без атомарной подмены рано или поздно прочитает половину json — а половина
json это не «неполные данные», это исключение вместо списка сессий.

Отпечаток состояния считается **без времени**, как в поллере пикера: `generated`
меняется на каждом такте, и сравнение целиком не дало бы экономии никогда.
Пишется файл при изменении отпечатка либо раз в 30 секунд — сердцебиение, по
которому читатель отличает «демон умер» от «ничего не менялось».

### Слияние в агрегаторе

`read_windows` читает старый одиночный файл **и** все файлы каталога.

- Свежесть у каждого файла своя: протухший (`generated` старше `WINDOWS_TTL`)
  выбрасывается целиком, как сейчас, и молча.
- Недоверие к содержимому остаётся прежним: порченая запись стоит себя, порченое
  поле — только поля, порченый файл — только этого файла.
- При слиянии запись окна получает `host`, `pid` и `canFocus` своего файла.
- Два трекера, претендующих на одну сессию, разводятся по большему `lastSeen`.

Ответ `--state` обрастает одним новым верхним полем — `windowHosts`, список
`{host, pid, canFocus}` по одному на живой трекер. Нужен он ровно для одного:
пикер должен отличать «моей машины среди трекеров нет» от «есть, но окон у неё
сейчас нет». По окнам этого не понять — у здорового трекера без открытых
терминалов список окон пуст.

Верхние `windowHost` / `windowPid` остаются как есть. Они кормят проектные
хоткеи, живущие в `projects`, и трогать их на этом этапе незачем.

### Правки в пикере

Сначала о том, чего править **не** придётся. `only windowed` и пометка ▣ живут
на одном лишь наличии поля `window` у строки и о хостах не знают ничего
(`opts.onlyWindow` в `session-groups.js` — это `rows.filter(r => r.window)`).
Они начинают работать на маке сами, как только у сессий мака появляется это
поле, и трогать их не нужно. Это и есть весь ответ на «рабочий чекбокс
`only windowed` для macOS»: чинится он не в пикере, а появлением источника.

Править нужно три места, и все три — про хост:

1. **`canFocus` смотрит построчно.** Вместо верхнего `state.windowHost` —
   `row.window.host`. Сегодня «чьи это окна» — свойство всего ответа; с двумя
   трекерами это свойство строки, и одно верхнее поле на него больше не
   отвечает.

2. **Ветка `focus` требует объявленного умения** (`row.window.canFocus`). Без
   этого заполненный `windowHost` в конфиге мака включил бы подъём, Enter
   отправил бы просьбу в MQTT — и окно поднял бы windows11-manager на другой
   машине. Проверка не косметическая: она единственное, что отличает «мой хост»
   от «мой хост, и он правда умеет».

3. **Заметка про чужие хоткеи меняет условие.** Сейчас статуслайн ругается,
   когда ответ несёт хоткеи для одного `windowHost`, а в конфиге пикера другой.
   На маке `windowHost` до сих пор оставляли пустым, и заметка молчала; теперь
   его придётся заполнить — иначе `canFocus` не с чем сверять, — и заметка
   начнёт ругаться всегда. Условие меняется на «нашего хоста нет среди
   `windowHosts` вовсе» — тогда она снова значит то, ради чего заведена:
   «настроили не ту машину».

## Отказы

Правило одно и общее: **отказ обязан стоить пометки, а не списка.**

| Что случилось | Что делает менеджер |
|---|---|
| Accessibility не выдано | Трекер стоит, файл **не пишется**, трей говорит прямо. Пустой файл означал бы «окон нет» и погасил бы чужие пометки; прежний протухнет по TTL сам, и это правда |
| ssh не дотянулся | Повтор с растущей паузой. Ничего не копится: следующая посылка везёт текущее состояние целиком |
| Дамп сессий не дотянулся | Привязка живёт на своих слотах — запасной путь тот же, что у `resolveSession` на Windows: новые заголовки не привязываются, известные держатся |
| Приложение не отвечает | `AXUIElementSetMessagingTimeout`, секунда на приложение |

Последняя строка — не мелочь. **Вызовы Accessibility синхронны и блокируются на
неотвечающем приложении.** Один подвисший iTerm вешает весь такт, трекер молча
перестаёт публиковать, а выглядит это как «менеджер умер». Без таймаута это
первое, что сломается.

## Тесты

| Где | Что проверяется |
|---|---|
| Rust, unit | Стабилизация заголовка, привязка, отпечаток без времени, решение «писать ли файл» |
| Агрегатор, python | Чтение каталога, отдельный TTL у каждого файла, слияние, конфликт двух трекеров на одну сессию |
| Пикер, node | Построчный `canFocus`, требование `canFocus` у ветки `focus`, условие заметки про хоткеи, сторож на то, что `only windowed` пропускает строку с окном чужой машины |

Логика трекера тестируется **без Accessibility** — так же, как
`tracker-helpers.test.js` в windows11-manager тестируется без Windows. Всё, что
трогает AX, живёт в `windows.rs` и в тестах не участвует.

## Выкатка

`data/scripts/deploy-mac.sh` в новом репозитории; каталог `data/` под
`.gitignore`, как в пикере, — скрипт знает имена машин и пути конкретной
установки, а не проекта.

Шаги: `git pull` на маке → `cargo build --release` → перезапуск. Автозапуск —
LaunchAgent.

Разово и руками:

- `rustup` на маке — Rust там сейчас не установлен вовсе;
- выдача Accessibility в System Settings.

**Проверка доезда:** файл `~/.ccfzf/windows/<host>.json` на remote-host свежее
тридцати секунд и не пуст; в пикере на маке появилась пометка ▣ и фильтрует
`only windowed`; список в пикере на Windows не изменился.

Последней задачей плана идёт **отдельная задача «Деплой на mac»** — по правилу
связки: код лежит на одной машине, а работает на другой, и до выкатки правка не
проверена ничем, кроме тестов.

## Решения, которые уже приняты

**Трекер целиком на маке, агрегатор только сливает.** Разбиралось и обратное —
мак шлёт сырые окна, а сводит заголовки с сессиями агрегатор, у которого дамп
под рукой. Ломается оно о то, что `ccfzf --state` — одноразовый вызов без памяти
между запусками, а привязка памятью и живёт: сессия правит заголовок терминала
на каждый ответ, дамп отстаёт до тридцати секунд, и слот — это ровно то, что
удерживает окно за сессией в промежутке. Без памяти окно мигало бы в списке
именно тогда, когда сессия работает. Чинится это «списком недавних заголовков» в
посылке — но тогда историю мак всё равно ведёт, то есть половина трекера
остаётся у него, а агрегатор вдобавок получает логику, которой у него нет, и
форматы двух трекеров расходятся.

**Rust, а не Node со Swift-помощником.** Accessibility доступен из Rust
(`accessibility-sys` / `objc2-application-services` поверх `core-foundation`),
и Tauri для трея на маке уже проверен соседним проектом. Вариант «логика на
Node, окна маленьким Swift-бинарём» дал бы переиспользование готовых
`tracker-helpers`, но ценой двух языков, двух шагов сборки и Xcode CLT в
зависимостях.

**Только Accessibility, без родных интерфейсов терминалов.** Цена известна и
принята: AX видит окна ОС, то есть **активную вкладку**. Сессия в фоновой
вкладке kitty считается сессией без окна. Заголовки всех вкладок отдают только
сами терминалы — `kitty @ ls`, AppleScript у iTerm2, — а у ghostty программного
интерфейса нет вовсе, и ему всё равно остался бы AX. То есть родные интерфейсы
дали бы три кодовых пути вместо одного и не покрыли бы всех.

Отдельно: `allow_remote_control` у kitty на маке сейчас выключен, так что этот
путь потребовал бы ещё и правки в настройках человека.

**Id сессии в командной строке `ssh` — запасной ход, не основа.** Пикер
запускает `ssh -t remote-host exec $SHELL -ic '… claude --resume <id>'`, и id
сессии виден в `ps` без всяких разрешений. Связать процесс с **окном** нечем:
tty→окно знает только сам терминал, а его удалённое управление выключено. Если
однажды включится — это точнее заголовков, и тогда стоит вернуться.

**Spaces не поддерживаются и не будут.** Программного интерфейса к виртуальным
столам у macOS нет. На Windows номер стола — заметная часть трекера
(`desktopRelearnTarget`, `desktopFollowTarget`, `releasedDesktop`); здесь этого
раздела не будет ни на одном этапе, и `desktop` в файле остаётся `null`.

## Этапы 2 и 3 — намерение, не проект

**Этап 2, «Enter поднимает окно».** Транспорт просьбы от пикера к менеджеру с
маршрутизацией по машине (иначе одну просьбу разберут оба менеджера), `AXRaise`
вместе с активацией приложения, `focusedAt` на переходе взгляда и «просмотрено»
из него, «Mark unread» с мака, объявленное умение поднимать переключается в
«да». Сюда же, если понадобится, открытие терминала силами менеджера с выбором
kitty / ghostty / iTerm2 — сейчас это делает пикер сам, и на маке уже работает.

Грамоты на передний план, вокруг которой построена вся Windows-ветка, здесь нет
и не нужно: macOS решает этот вопрос разрешением, выданным человеком один раз.

**Этап 3, «снимки и расстановка».** Геометрия через `AXPosition` / `AXSize`,
запоминание позиций, снимки раскладки, восстановление. Без Spaces.
