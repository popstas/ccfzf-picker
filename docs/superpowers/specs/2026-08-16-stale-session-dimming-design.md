# Затемнение старых сессий и проектов

## Цель

Добавить отключённый по умолчанию режим, который визуально отодвигает старые
сессии и проекты, не скрывая их и не меняя порядок списка. Наведение мышью или
выбор с клавиатуры возвращает строке полную непрозрачность.

## Настройки

Режим хранится в `config.yaml` отдельной группой:

```yaml
stale:
  enabled: true
  sessionHours: 2
  projectDays: 7
```

Во вкладке General появляются три поля:

- `Dim stale sessions and projects` — галка включения;
- `Sessions become stale after, hours` — положительное число, по умолчанию 2;
- `Projects become stale after, days` — положительное число, по умолчанию 7.

`projectDays` — один общий порог для всех проектов, а не настройка отдельного
проекта. Он переопределяет для проектов общий смысл «старого элемента», чтобы
редко открываемые проекты не затемнялись уже через два часа.

Отсутствующая или некорректная группа нормализуется в
`{ enabled: false, sessionHours: 2, projectDays: 7 }`. Форма не сохраняет
нулевые, отрицательные и нечисловые пороги и показывает ошибку рядом с кнопкой
Save. Выключение режима сохраняет введённые пороги: при повторном включении
человеку не нужно настраивать их заново.

## Определение старой строки

Единственный источник времени — существующее поле `lastActivity` в epoch-
секундах. Оно уже есть и у сессий, и у строк проектов. Отдельные часы и новое
состояние не вводятся.

При включённом режиме строка считается старой, если:

- для любой обычной сессии, независимо от `live`, состояния агента, группы и
  наличия окна, `nowSec - lastActivity >= sessionHours * 3600`;
- для проекта `nowSec - lastActivity >= projectDays * 86400`.

Нулевой, отсутствующий или нечисловой `lastActivity` означает неизвестный
возраст и не затемняет строку. Заголовки секций, снимки раскладки и строки
Zellij в эту задачу не входят.

## Отрисовка

Расчёт оформляется небольшим чистым помощником, который по строке, текущему
времени и нормализованным настройкам отвечает, нужна ли строке метка `stale`.
`sessionItem` и `projectItem` используют один помощник и добавляют класс к
корневому `.row`, не меняя разметку её содержимого.

CSS задаёт старой строке `opacity: 0.5`. Правила `.row.stale:hover` и
`.row.stale.active` возвращают `opacity: 1`, поэтому наведённая строка и
клавиатурный выбор полностью читаемы. Анимация и отдельные цвета не нужны.
Синхронизация списка продолжает работать по существующим ключам строк: при
переходе порога изменяется только HTML этой строки.

## Поток данных

1. `config.yaml` загружается и нормализуется вместе с остальной конфигурацией.
2. Настройки stale входят в `CONFIG`, уже доступный странице пикера.
3. На очередном тике построитель строки сравнивает `lastActivity` с `nowSec`.
4. Старая строка получает класс `stale`; CSS управляет прозрачностью и её
   восстановлением при hover или выборе.

Новых команд Tauri, файлов состояния и событий между окнами не требуется.

## Проверка

Автоматические тесты должны подтвердить:

- нормализацию отсутствующих, корректных и некорректных stale-настроек;
- отображение defaults в Settings и точечный патч после изменения каждого
  поля;
- отказ формы сохранять неположительные пороги;
- границу порога для сессии и проекта;
- одинаковое затемнение живой, закрытой, оконной и безоконной старой сессии;
- отсутствие затемнения при выключенной галке и при неизвестном
  `lastActivity`;
- наличие CSS-правил полной непрозрачности для `.stale:hover` и
  `.stale.active`.

Итоговая проверка фронтенда — `npm test`.
