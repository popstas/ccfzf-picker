# Реестр терминалов: выбор в пикере главнее, wt и WezTerm равноправны

Дата: 2026-08-16. Затрагивает три репозитория: `ccfzf-picker`,
`windows11-manager`, `macos-windows-manager`. Агрегатор `ccfzf` не трогается.

## Зачем

На popstas-pc выбран пресет WezTerm, `config.yaml` записан верно
(`file: wezterm-gui.exe`, `args: [start, --]`), а открывается Windows Terminal.
Пресет не при чём: на машине с трекером и настроенным брокером
`chooseEnterAction` (`frontend-src/open-transport.js`) отдаёт `manager`, и
терминал поднимает windows11-manager своим конфигом. Поле `terminal` в
`config.yaml` читается только на запасной местной дороге — то есть на этой
машине почти никогда.

На маке WezTerm не открывается по другой причине — там как раз работает местная
дорога, и в ней ошибка; чинится отдельно (см. «Побочная задача»).

Требование владельца: **выбранное в пикере главнее**; у менеджера может быть
свой терминал по умолчанию, но он обязан принимать и другой; на Windows wt и
WezTerm равноправны; интерфейс общий и не привязан к системе — пикер чистый,
ос-специфику несёт менеджер окон.

## Решения, принятые до дизайна

1. Правим все три репозитория в одной работе.
2. `macos-windows-manager` становится зеркалом Windows-менеджера **по открытию
   сессий**: принимает `claude-session-open`, объявляет `openSession: true`.
   Снимки раскладки, `claude-focus-slot` и проектные хоткеи на маке в эту
   работу не входят.
3. Местная дорога пикера остаётся как есть — со своей таблицей пресетов. Она
   работает там, где менеджера нет: лёг брокер, не запущен трекер, машина без
   менеджера вовсе.
4. Зеркальность может быть только интерфейсной. У Windows-менеджера вся логика
   в JS (`src/mqtt/*`, `src/claude-wt/*`), а Tauri-часть — надзиратель над
   node-демонами; у мак-менеджера всё в Rust (`mwm-core` + `src-tauri`). Общего
   кода нет и не заводится: повторяется контракт, как уже сделано с файлом
   трекера (`crates/mwm-core/src/publish.rs` намеренно повторяет формат
   JS-овского `src/claude-wt/windows-file.js`).

## Отвергнутые устройства

**Просьба несёт готовую команду** (`{command, args}` прямо из конфига пикера).
Пикер на маке шлёт просьбу и Windows-машине — его `terminal.file` там путь,
которого не существует. Вместе с командой пришлось бы везти и знание про `-w -1`
и профили, то есть вернуть ос-специфику в пикер.

**Выбор хранится у менеджера, пикер меняет его отдельной просьбой.**
Появляется состояние, которое надо держать и переживать перезапуск, а просьба
перестаёт быть самодостаточной: на каждую машину свой запомненный выбор. И
«приоритет за выбранным в пикере» становится не свойством просьбы, а
результатом удачной синхронизации.

## Контракт

### Тело просьбы

Топик прежний, `<база машины>/claude-session-open`. Поле одно новое:

```json
{"action":"terminal",     "id":"<sessionId>", "cwd":"<dir>", "terminal":"wezterm"}
{"action":"terminal-new", "cwd":"<dir>", "name":"<name>",    "terminal":"wezterm"}
```

`terminal` необязателен. Пустая строка, отсутствие ключа и незнакомое имя —
менеджер берёт свой дефолт и пишет об этом строку в лог. Отсюда следует, что
порядок выкатки не важен: старый пикер с новым менеджером ведёт себя как
сегодня, новый пикер со старым менеджером — тоже (лишнее поле игнорируется).

### Словарь имён

`wt`, `wezterm`, `kitty`, `ghostty`, `iterm2`. Имена без системы в названии:
WezTerm на маке и на Windows зовётся одинаково, а что за именем стоит, знает
только принимающая сторона. «Custom» в настройках пикера имени не имеет — тогда
поле не отправляется вовсе.

### Реестр терминалов у менеджера

Форма одна, синтаксис свой. Windows (`%APPDATA%\windows-mqtt\windows11-manager.config.js`):

```js
claudeWt: {
  terminal: 'wt',                     // дефолт машины
  terminals: {
    wt:      { command: 'wt.exe',          args: ['-w','-1'], profileArgs: ['-p','{profile}'] },
    wezterm: { command: 'wezterm-gui.exe', args: ['start','--'] },
  },
  launch:    { args: ['ssh','-A','user@host','-t','ccfzf --session {id} --kiosk'] },
  launchNew: { args: ['ssh','-A','user@host','-t', "exec $SHELL -ic '…' claude-wt '{cwd}' '{name}'"] },
}
```

Мак — то же в YAML под ключом `claude:`.

**Команда собирается сложением:** `terminals[name].command` + его `args` +
`profileArgs` (если у проекта есть профиль для этого терминала) + `launch.args`.
Сегодня терминальная часть и ssh-хвост лежат в `launch.args` одним плоским
списком — разделение этих двух и есть суть правки.

Подстановки прежние: `{id}`, `{cwd}`, `{name}`; добавляется `{profile}` внутри
`profileArgs`.

### Профили

Карта у записи проекта, ключ — имя терминала:

```js
projects: [{ name: 'site', cwd: 'X:\\projects\\site', hotkey: 'Ctrl+F11',
             profiles: { wt: 'Site', iterm2: 'Site' } }]
```

Нет ключа для выбранного терминала — профильные аргументы не добавляются вовсе.
Старое плоское поле `profile` читается как `profiles.wt`: иначе первая же
выкатка обнулила бы владельцу все профили.

### Обратная совместимость

Остался `launch.command` — конфиг считается старым, реестр игнорируется,
поведение прежнее, в лог уходит строка о том, почему выбор терминала не
действует. Конфиг на popstas-pc переписывается под новую форму отдельным шагом,
с бэкапом.

## Что делает каждый репозиторий

### ccfzf-picker

- У пресета появляется семейное имя (`terminal: 'wezterm'` у обоих
  WezTerm-пресетов и так далее) — `frontend-src/terminal-presets.js`.
- Имя уезжает в теле **всех трёх** просьб, кончающихся терминалом:
  `mqtt::open`, `mqtt::open_project` и `mqtt::open_new`
  (`src-tauri/src/mqtt.rs`) — то есть Enter на сессии, Enter на строке проекта
  и `^N`. Просьба проектного хоткея (`project_hotkeys.rs`) идёт тем же
  `open_project` и получает имя оттуда же.
- **Имя вычисляется в Rust, а не на странице.** Просьбу шлёт и
  `project_hotkeys.rs` — при спящем webview. Своего ключа в конфиге у пресета
  нет намеренно (записано в CLAUDE.md: второй источник правды разошёлся бы с
  полями, которые правят руками), поэтому `terminal.name` в `config.yaml` не
  заводится. Остаётся маленькая таблица «чем открывают → имя» в Rust и
  текстовый сторож, сверяющий её с JS-таблицей. Приём в проекте уже работает:
  так живут `MODE_MENU` в Rust и `PREFIXES` в JS (`test/tray-modes.test.js`).
- Местная дорога не меняется.

**Сделано (2026-08-17), с одним отступлением от написанного здесь.** Ключ
таблицы в Rust — **имя файла без каталога**, а не «file+args», как задумывалось.
Причина в том, что вопросы у двух таблиц разные: `matchPreset` в окне настроек
отвечает «пресет или Custom», и дописанный руками флаг обязан честно дать
Custom; `terminal_name` отвечает «какой это терминал», и на это ни флаг, ни
каталог не влияют. Полный путь ключом не годится вовсе — у msi,
portable-распаковки и scoop он разный, а терминал один, и такой ключ отправлял
бы просьбу без имени тому, у кого WezTerm лежит не в PATH. Неточная запись в
таблице одна, `osascript` → `iterm2`; цена её сегодня нулевая — просьбы об
открытии сессии на маке не принимает никто.

### windows11-manager

- Реестр `claudeWt.terminals` и дефолт `claudeWt.terminal`; сборка команды
  сложением вместо плоского `launch.args`; профили из `projects[].profiles`.
- `applyWtProfile` (`src/claude-wt/wt-profile-helpers.js`) остаётся только на
  старой дороге: в новой профиль приезжает шаблоном из реестра, и вырезать
  чужие `-p` не нужно.
- Опознание окна терминала: сегодня регулярка по `WindowsTerminal.exe`
  (`src/claude-wt/daemon-helpers.js:49`). Станет список исполняемых с
  умолчанием `WindowsTerminal.exe` + `wezterm-gui.exe`, переопределяемый в
  конфиге. Без этого окно WezTerm трекер терминалом не признает: сессия
  откроется, но пропадёт из виду — ни ▣, ни фокуса, ни привязки.

### macos-windows-manager

- Команда `claude-session-open` в `crates/mwm-core/src/request.rs` (сегодня
  понимаются две: `claude-focus`, `claude-session-unread`), те же поля и та же
  терпимость к форме тела (объект, json-строка, сырая строка).
- Реестр терминалов в `~/.config/macos-windows-manager/config.yaml`, дефолты в
  коде, сборка argv, `spawn` открепления.
- Ветвление как на Windows: сессия известна слотом — поднять окно; иначе
  открыть по `cwd`; иначе отказ в лог.
- `openSession: false` → `true` (`crates/mwm-core/src/publish.rs:97`), вместе с
  переписыванием сторожа `this_machine_does_not_open_sessions`.
- WezTerm в умолчание списка `terminals` (bundle-id `com.github.wez.wezterm`) —
  это список наблюдаемых приложений, не реестр запуска; имена рядом, а смысл
  разный.
- **iTerm2 — самая дорогая часть.** Команду он не принимает ни в argv, ни
  строкой без риска: его токенизатор ломает идиому `'\''`. Пикер отдаёт ему
  путь помощника и base64 (`terminal_helper` в `src-tauri/src/main.rs`), и этот
  механизм — запись помощника, base64, подстановки `{helper}` и
  `{commandBase64}` — переезжает в мак-менеджер. В пикере он остаётся: местная
  дорога живёт.

### ccfzf

Не трогается. `openSession` агрегатор уже читает и умеет; новых полей контракт
не вводит.

## Побочная задача — проверена и снята

«WezTerm на маке не открывается» — это местная дорога пикера, и она остаётся.
Догадка была такая: в бандле лежит и `wezterm`, и `wezterm-gui`, а пресет
(`frontend-src/terminal-presets.js`) называет первый — значит, как и на Windows,
надо звать второй.

**Проверено живьём 2026-08-17 и не подтвердилось.** `wezterm` из бандла сам
перезапускается в `wezterm-gui`: под настоящим argv пресета
(`/Applications/WezTerm.app/Contents/MacOS/wezterm start -- ssh -t <host> "exec
$SHELL -ic '…'"`) в `ps` стоит `…/MacOS/wezterm-gui start -- ssh -t`, окно с
сессией открывается, stderr пуст. Консольного окна на маке не бывает вовсе —
ради него развилка и заведена на Windows, — то есть переносить её сюда было бы
правкой без причины. Замер записан в CLAUDE.md рядом с самим пресетом.

Заодно: на маке в `config.yaml` сейчас стоит iTerm2, а не WezTerm, — то есть
исходное наблюдение относилось к прежней настройке и сегодня не
воспроизводится.
