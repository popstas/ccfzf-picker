# Два источника состояния: удалённый агрегатор и местный, в одном списке

Дата: 2026-08-18. Репозиторий один — этот. Соседний `~/projects/shell/ccfzf`
приезжает сюда подмодулем и не правится; трекеры окон
(`windows11-manager`, `macos-windows-manager`) не трогаются вовсе — про них
отдельная задача, см. «Что сюда не входит».

## Зачем

Пикер сегодня спрашивает ровно один агрегатор: `state_source::fetch` умеет одну
дорогу — `ssh <sshHost> "ccfzf --state"`, и хоста без ssh не бывает (пустой
`sshHost` — ошибка конфигурации, сторож `empty_ssh_host_is_a_config_error`).
Из этого следуют две вещи, каждая из которых видна человеку как пропажа.

**Местных сессий в списке нет.** Агент, запущенный на той же машине, где стоит
пикер, не показывается никак: спрашивают не его машину. Человек, работающий и
на общем хосте, и у себя, держит два списка в голове.

**Пикер без общего хоста не работает вовсе.** Поставивший его рядом с обычным
`claude` — без выделенной машины для агентов, без оконного трекера, без
`ccfzf` — видит сообщение «sshHost is not set» и ни одной строки. При том что
всё, что нужно для списка, лежит у него в `~/.claude/projects`.

Задача закрывает оба случая одним понятием — **источник состояния**, — и
оставляет сегодняшнее поведение умолчанием.

## Что решено человеком

- Второй источник задаётся булевым флагом `localSource: true`, а не списком
  хостов: список обещал бы N машин, а спрошены две.
- Местный источник зовётся **напрямую, без ssh**. `ssh localhost` рассматривался
  и отвергнут: он требует поднятого sshd и своего ключа в `authorized_keys` —
  на macOS Remote Login по умолчанию выключен, на Windows сервера нет вовсе, то
  есть сценарий «поставил и увидел свои сессии» не сработал бы ровно там, ради
  чего затевался.
- `ccfzf` берётся из PATH, если он там есть; иначе — вендорная копия,
  git-подмодуль на `popstas/ccfzf`.
- Спека покрывает и слияние источников, и вендоринг: без второго первый не
  отвечает на «чистый claude», а без первого второй некуда встроить.

## Устройство

### 1. Источник

В Rust вместо строки `ssh_host` живёт список:

```rust
enum Source {
    Ssh(String),  // sshHost из конфига — как сегодня
    Local,        // ccfzf на этой машине, без ssh
}
```

Считает список одна функция из конфига (`sources_from(&config)`): `sshHost`
даёт `Ssh` (пустой — не даёт ничего), `localSource: true` добавляет `Local`.
Порядок обязателен и назван: удалённый первым — он и есть «общий» источник, а
дедуп ниже разрешает споры в пользу первого.

Поле конфига — `localSource`, умолчание `false`. Умолчание не «удобное», а
единственно честное: включённый по умолчанию местный источник на машине без
`ccfzf` и без python3 добавил бы всем существующим установкам строку об отказе
там, где сегодня всё работает.

**Местный источник — Linux и macOS.** `ccfzf` это bash-обёртка вокруг
встроенной python-программы (`py() { printf '%s\n' "$PY" | python3 - "$@"; }`),
и на нативном Windows не запустится ни вендорная копия, ни системная. Галка в
окне настроек говорит об этом подписью, а не молчит; на Windows у человека
остаётся обычный `sshHost` (в том числе `localhost`, если он сам поднял sshd) —
но это уже не «из коробки», и обещать обратное нельзя.

### 2. Слияние — в Rust, форма ответа прежняя

`lastState` на странице — один документ агрегатора, и вся страница живёт его
полями: `lastState.hosts`, `lastState.snapshots`, `lastState.windowHost`,
`openIdsFromState(lastState)`, `mqttBaseFor(row, lastState, …)`. Отдай Rust два
документа — правок было бы не десять, а сто, и каждая из них молчаливая.

Поэтому слияние живёт в Rust и отдаёт **тот же самый документ**. Чистая функция
рядом с `state_source`:

```rust
fn merge_states(parts: Vec<(Source, serde_json::Value)>) -> serde_json::Value
```

Правила:

- `sessions`, `projects`, `snapshots`, `zellij` — конкатенация; каждой записи
  проставляется `source` — строка: для `Ssh` это `sshHost` дословно, как он
  записан в конфиге (в том числе в форме `user@host`), для `Local` — литерал
  `local`. Дословно, а не приведённым к имени машины: этой же строкой потом
  адресуются действия, и приведи её пикер к «красивому» виду — ssh пошёл бы
  не туда.
- **Дедуп по `id`, первый источник побеждает; списки `windows` склеиваются.**
  Это не перестраховка. Пикер, стоящий на той же машине, что и `sshHost`,
  получит от обоих источников один и тот же список целиком — и без дедупа
  человек увидел бы каждую строку дважды. Дедуп делает этот случай безвредным,
  и потому отдельной проверки «а не та ли это машина» не заводится: второй
  признак того же самого разошёлся бы с первым, а сравнивать было бы нечего —
  имени своей машины в ответе агрегатора нет.
- `hosts` — слияние по имени машины; запись первого источника побеждает.
- `generated` — **минимальное** из двух: ответ настолько свеж, насколько свеж
  самый старый его кусок. Максимум соврал бы про возраст всей половины.
- Верхние `windowHost`/`windowPid` — от первого источника. Это легаси-путь для
  старого агрегатора (окно одно на весь ответ), и второй источник его не
  касается.

`fingerprint` (`poller.rs`) считается по слитому документу: бэкофф остаётся
один на пикер, как и такт опроса. Разные такты у источников рассматривались и
отвергнуты — второй счётчик задержки разошёлся бы с первым, а выигрыш
(местный вызов дешевле ssh) на секундном такте показанного окна нулевой.

### 3. Машина у строки без окна

`activeGroups` (`frontend-src/session-groups.js`) считает своей всякую строку с
пустым `windowHost`, и при одном источнике это верно: «чужой строку делает
названная чужая машина, а не отсутствие сведений» — иначе на маке, где трекера
может не быть вовсе, весь список уехал бы в remote.

С двумя источниками это соврёт: удалённая сессия без окна встанет в «Active
local sessions» рядом с настоящими местными, и отличить их будет нечем.

Поэтому у сессии **без записи окна** машину подставляет источник:
`Ssh(host)` → `host`, `Local` → пусто (своя). Ставится это в `buildSessionList`
(`frontend-src/session-list.js`), там же, где сегодня считается `windowHostOf`.
Второго места для «чья это машина» заводить нельзя — оно разошлось бы с первым
молча, а видно это было бы только тем, что строка стоит не в том блоке.

Запись окна по-прежнему главнее источника: окно называет машину, на экране
которой сессия видна, а источник — только машину, у которой про неё спросили,
и это разные вопросы. Сессия, открытая на общем хосте и показанная в окне
мака, обязана остаться в блоке мака.

### 4. Каждое действие ходит к своему источнику

`CONFIG.sshHost` перестаёт быть адресом действий: адрес берётся у строки.
Места, все проверены по коду:

| место | сегодня |
|---|---|
| `buildOpenCommand` (`open-strategy.js`) | `['ssh','-t',sshHost,remote]` |
| `newSession` / Enter на строке проекта (`sessions.html`) | `ssh -t CONFIG.sshHost` |
| комментарий (`sessions.html` → `set_comment`) | `sshHost: CONFIG.sshHost` |
| текст предупреждения о перехвате | `…on ${CONFIG.sshHost} will get SIGHUP…` |
| подсказка «paste it into a terminal on …» | `CONFIG.sshHost` |
| `sshHostMissing()` | проверка одного поля |

У местного источника хвост argv собирается **без ssh**: не
`['ssh','-t',host,remote]`, а `[shell,'-c',remote]`. Сама строка `remote` не
меняется — `exec $SHELL -ic 'cd -- <cwd> && claude …'` нужна ровно затем же,
зачем и на удалённой машине: поднять интерактивный шелл, чтобы отработал хук
`chpwd` и телеметрия получила имя проекта. Правило `q` остаётся: команду
по-прежнему разбирает шелл, просто свой, а не чужой.

Ветка добавляется в `terminalArgv`, а не у вызывающих. Причина записана в коде
и оплачена живьём: `newSession` однажды собирал argv у себя и про подстановку
`{command}` не знал, отчего `^N` на iTerm2 не работал никогда. Сторож «страница
не собирает argv терминала мимо terminalArgv» стоит и обязан продолжать
ловить.

`set_comment` для местной строки зовёт `ccfzf --comment` тем же способом, что и
`--state`: тот же выбор бинаря, тот же stdin для текста (аргументом текст
уходить не должен — это разбираемая шелом строка, и `fix; rm -rf ~` был бы там
командой).

### 5. Где брать `ccfzf` локально

Порядок: **PATH, иначе вендорная копия**.

PATH первым намеренно. На машине, где `ccfzf` уже стоит, он же переписывает
`~/.ccfzf.sessions.json` и `~/.ccfzf.projects.json` — дампы, с которых живут
оконный трекер, экспорт в Home Assistant и панель openHASP. Две разные версии
над одним файлом были бы бедой, которую видно не сразу и не здесь.

Вендорная копия — `vendor/ccfzf`, git-подмодуль на `git@github.com:popstas/ccfzf.git`,
закреплённый коммитом. Подмодуль, а не копия файла: копия тихо стареет, а по
подмодулю видно версию и обновляется он одной командой. Плата известна:
`data/scripts/deploy-*.sh` первым шагом делают `git pull` на целевой машине, и
ему нужен `--recurse-submodules` — без него на той стороне окажется пустой
каталог, а отказ будет выглядеть как «ccfzf не найден».

Ни одного нового условия на сборку это не добавляет: `--state` требует bash и
python3, но требует их **в момент запуска**, а не компиляции.

### 6. Отказ одного источника не гасит второй

Сегодня отказ `fetch` — ошибка на весь пикер. С двумя источниками правило
другое: список показывается по тем источникам, которые ответили, а отказавшие
называются в статуслайне поимённо — `local: ccfzf not found`,
`remote-host: ssh exited with 255: …`.

Молчаливое выпадение половины списка — худшее, что здесь может случиться:
пропавшие сессии читаются как «сессий нет», а не как «спросить не удалось», и
человек пойдёт искать сессию, а не чинить ssh.

Отказ **всех** источников — прежняя ошибка на весь список, дословно тем же
текстом, каким она приходит сегодня.

Пустой `sshHost` при включённом `localSource` перестаёт быть ошибкой
конфигурации: источник есть, просто он один. `check_ssh_host` и
`sshHostMissing()` заменяются на проверку **пустого списка источников** — иначе
получилось бы два правила про одно и то же, и второе молчало бы.

## Что сюда не входит

- **Трекинг окна местного claude** — это `windows11-manager` и
  `macos-windows-manager`. Пикер окон не видит вовсе и видеть не должен: они
  приезжают в ответе агрегатора из файла трекера. Без этой работы местные
  сессии будут без пометки ▣ и без подъёма окна по Enter — ожидаемо, а не
  поломка. Уходит отдельной задачей в `docs/TODO.md`.
- **Живость местных сессий вне Linux.** `running_sessions()` в агрегаторе
  читает `/proc`; на macOS он вернёт пусто, и живость останется только от
  `live_by_hook()` — свежей отметки хука в `~/.claude/claude-wt/<id>.state.json`
  (TTL 120 с). У человека без этих хуков местные сессии на маке приедут
  историей: `cwd`, `title`, `mtime` верные, `live` пустой. Чинится в
  агрегаторе, а не здесь.
- **Windows как местный источник.** См. раздел 1.
- Третий и последующие источники: машинерия списочная, конфиг — нет.

## Проверка

Фронтенд — `npm test`, оболочка — `cd src-tauri && cargo test`.

- `merge_states`: дедуп по `id` (в том числе полное совпадение двух ответов —
  тот самый «пикер на машине агрегатора»), склейка `windows` у одинакового id,
  `generated` по минимуму, слияние `hosts`, пустой второй источник, ответ без
  `projects`/`snapshots` (старый агрегатор).
- `sources_from`: `localSource` включён / выключен / отсутствует; пустой
  `sshHost` с `localSource: true` даёт один источник, без него — ноль.
- Выбор бинаря: PATH → вендорный → отказ с внятным текстом.
- `terminalArgv` для местного источника на всех четырёх пресетах, включая
  iTerm2 с его `{helper}` и base64 — местная ветка обязана пройти той же
  дорогой подстановок.
- Атрибуция машины у строки без окна: обоими источниками, и приоритет записи
  окна над источником.
- Статуслайн при отказе одного источника и при отказе обоих.
- Живьём: пикер на этой машине с `localSource: true` и настоящим `sshHost` —
  оба списка в одном окне, Enter на местной строке открывает терминал здесь,
  Enter на удалённой — по ssh.

## Риски

- **Дедуп прячет настоящее совпадение id.** Один id на двух разных машинах
  теоретически возможен (перенесли `~/.claude`), и тогда вторая сессия
  исчезнет из списка. Считаем приемлемым: id — uuid, а альтернатива (ключ
  `id@source`) сломала бы `seen.json`, ключи строк и всё, что опирается на id.
- **Вендорный `ccfzf` расходится с системным.** Живёт подмодулем, обновляется
  руками; правило «PATH первым» делает расхождение безвредным на машинах, где
  `ccfzf` стоит.
- **Двойная выкатка.** Пикер и агрегатор выкатываются порознь; новый пикер
  обязан работать со старым ответом `--state` — поэтому поле `source`
  проставляет сам пикер, а не агрегатор.
