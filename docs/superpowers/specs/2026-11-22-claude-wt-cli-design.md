# CLI `claude-wt`: один инструмент агента для окон и сессий

Дата: 2026-11-22. Источник: задача «Единый CLI харнеса по образцу `agtermctl`»
в `docs/TODO.md`, разговор в сессии picker-do-head. Прочитан рецензентом-
строителем; расхождения с кодом, которые он нашёл, исправлены ниже.

## Зачем

Стас: «хочу дать агентам единый инструмент управления окнами сессий, cli+skill,
сейчас это разбросано по разным интерфейсам».

Пользователь инструмента — агент: head-сессия и её исполнители. Сегодня агент
управляет **сессиями** через отдельные скрипты скиллов (`session-spawn`,
`session-find`, `session-rename`, `session-close`, `head-session` с
`head-mark`/`head-adopt`/`lineage`, вместе ~860 строк `.mjs`), а **окнами** не
управляет вовсе: поднять окно, разложить группу, восстановить снимок можно
только кнопками пикера, http-путями менеджера windows11-manager или публикацией
в MQTT.

## Цели

- Одна команда `claude-wt <группа> <действие> [--json]`: одна команда за вызов,
  вывод для машины (`--json`) и короткий для человека, код выхода по смыслу.
- Один скилл к ней: что можно, что нельзя, рецепты.
- Окна (шаг 1): поднять окно своей сессии, разложить свою группу head,
  восстановить снимок, прочитать всю картину одним `tree --json`.
- Сессии (шаги 2–6): команды скиллов `session-*` и `head-*` переезжают внутрь
  CLI по одной; скиллы на каждом шаге продолжают работать и в конце становятся
  тонкими ссылками на CLI или уходят.

## Не цели

- Окна, которые скрипт зовёт и ждёт ответа человека (`pick`, `ask`, `hud` у
  agterm): пользователь — агент, а для этих окон пикеру нужен вход снаружи.
- Мак: недоступен с конца октября, его трекер просьб об открытии не принимает
  (`openSession: false`). Файл мака в `~/.ccfzf/windows/` CLI не роняет, но
  команды туда не шлёт.
- `place --zone`, `seen`, `unread` — убраны из шага 1 (решение head, см. ниже).
- Смена политики: закрытие сессий остаётся по правилу head-session (только с
  явного подтверждения пользователя по конкретной сессии), запрет
  `bypassPermissions` у детей — тоже.

## Анти-цели (провал, даже если «работает»)

- Сломать живые скиллы посреди переезда: на них в эту минуту стоят исполнители.
  Скрипты скиллов лежат в локальном git-репозитории `~/.claude/skills` (без
  remote) вместе с тестами `~/.claude/skills/test/{spawn,close,head-mark,
  head-adopt}.test.mjs` и `harness.mjs`; шимы обязаны проходить именно их, с
  их подменами окружения (`CCFZF_HEADS_DIR`, `CCFZF_CHILDREN_DIR`,
  `SPAWN_TEST_HEAD_MODE`). У `find.mjs` и `rename.mjs` тестов нет — завести до
  переезда.
- Молчаливый успех: команда вернула 0, а окно не поднялось.
- Агент, открывший новое окно, думая, что переключает фокус.
- Имена машин, домашние пути, имена клиентских проектов в публичном репо.

## Решения Стаса (2026-11-22)

- Вариант «один CLI, по шагам»: сначала окна и `tree`, потом команды сессий
  переезжают по одной, старые скиллы перенаправляются на CLI.
- **Агенту разрешены `focus` и `layout` без спроса**, хотя они уводят ввод у
  человека, если он печатает в другом окне.
- **`focus` только поднимает существующее окно.** Окна нет — отказ «окна нет»,
  ничего не открывается. Открыть сессию — отдельная команда (`session open`,
  позже, не в шаге 1).
- **`session open` — можно без спроса для своей сессии** (решение 2026-11-22, позже в тот же день): отдельная команда, открывает окно, когда его нет.
- **Агент действует пока только над своими сессиями.** Чужие (сессии Стаса,
  другие head и их группы) — отказ.

## Решения head (Стас их не обсуждал — можно поправить)

- **«Свои» сессии.** Вызывающая сессия (её id — `CLAUDE_CODE_SESSION_ID`, как у
  `spawn.mjs`) и все её потомки по `~/.ccfzf/children` (`lineage.mjs`). Для
  head это он сам, его дети и усыновлённые, вглубь; для исполнителя — только он
  сам и его собственные дети. `layout <head>` разрешён, если `<head>` — сам
  вызывающий или его потомок. Снимок: восстанавливать можно только снимок,
  все сессии которого — свои (или с `--sessions`, отфильтрованными до своих).
  Вне Claude Code (переменной нет) — отказ для всех команд действия; `tree`
  работает всегда.
- **Имя и место кода.** Команда `claude-wt`, код — в репозитории ccfzf
  (публичный): он уже поставляет `claude-wt-new` и хуки (`hooks/`, ccfzf#28).
  Установка — симлинком из основного клона, как `~/bin/ccfzf` и хуки.
  Переезжающие скрипты упоминают имена машин и репозиториев (`spawn.mjs`,
  `find.mjs`, SKILL.md) — при переносе вычищать, конкретику брать из файлов
  трекера и окружения.
- **Скилл остаётся в `~/.claude/skills`** (локальный git), а не в ccfzf: в нём
  неизбежно живут цели выкатки и имена машин. Новый скилл `claude-wt-cli`, а не
  расширение `claude-wt` (тот — карта связки для человека-разработчика, а не
  инструкция агенту).
- **Язык — Node** (ESM, без зависимостей, Node ≥ 18 — встроенный `fetch`).
- **Где работает.** На машине агентов (ssh-хост агрегатора, Linux).
- **Куда слать команду.** Трекеру той машины, где стоит окно сессии
  (`sessions[].window.host` / `windows[].host` из `ccfzf --state`), если у него
  есть `http` в файле трекера; иначе отказ с причиной. `--machine`/`--url`
  перебивают. Снимки — только трекеров с `http`; `last` — самый свежий среди
  них.
- **Транспорт — только http менеджера.** MQTT-ветку CLI не заводит: у MQTT нет
  ответа.
- **`place --zone` убран из шага 1**: пути для него в менеджере нет
  (`/claude-wt/place` знает только `tile`/`cascade`/`group`, зоны есть только у
  `session-new` в `child-place.js`) — это новая работа в менеджере, отложена.
- **`seen`/`unread` убраны из шага 1**: отметок «просмотрено» две, они
  складываются по максимуму (местный `seen.json` пикера и `focusedAt` трекера,
  `docs/rules/windows-and-focus.md`). Через менеджер `session-seen` гасит только
  кнопку на панели задач, `unread` откатывает только `focusedAt` — точку в
  пикере агент так не изменит, а вход в пикер снаружи — не цель.
- **`layout <head>`** — `{mode: "group", groups: [[head, ...потомки с окнами]],
  selected: head}` на `/claude-wt/place`, без точного повтора правил группировки
  пикера (`nestByHead`, `place_order::group_ids`, фикстура
  `test/fixtures/head-groups.json`): агенту нужна раскладка своей группы, а не
  совпадение с Ctrl+Win+F10 до порядка вложенных групп. Потомки без окна в
  группу не входят.

## Ответы менеджера: как есть и что меняется

Как есть (сверено рецензентом с кодом):

- http-слушатель (`replyResult` в `src/http-server.js`) отвечает `200
  {ok:true, ...result}`; обработчик, вернувший `undefined`, даёт `200
  {"ok":true}` — то есть сегодня `focus`, `place`, `session-unread` отвечают
  «успехом» без всякой проверки. Обработчик, вернувший `{ok:false, reason}`,
  даёт `200` с `ok:false` в теле (так уже отвечают ветки `session-open`).
  `httpStatus` в результате превращается в код ответа.
- Пикер (`manager_http.rs`) код ответа читает: не-2xx — отказ со строкой
  `error`, доезжает до статуслайна; тело 2xx не читает.
- `/claude-wt/focus` — не чистый подъём: окна нет — `focusOrRestore` открывает
  терминал заново (`chooseAction` → `restoreOne`); не вышедший вперёд подъём
  (`focusTerminalWindow` → false) — тоже `ok`, только warn в журнал.
- `/claude-wt/snapshot-restore` отвечает сразу, восстановление идёт хвостом до
  30 с.

Что меняется в windows11-manager (часть шага 1):

- Отказы — `200 {ok:false, reason}`, **не** 4xx/5xx: пикер тогда ничего нового
  в статуслайне не покажет, а CLI смотрит на тело. Пикер не трогается.
- `focus` получает режим «только поднять» (поле в теле, например
  `{id, raiseOnly: true}`; имя — строителю): окна нет — `{ok:false, reason:
  "no window"}`, без restore. Без поля — как сегодня (пикер и панель не
  меняются).
- `focus` и `place` отвечают, вышло ли окно вперёд (`foreground: true|false`);
  CLI считает `false` отказом (код 1, «окно не вышло вперёд»).
- `snapshot-restore` — как есть: «принято», исход в журнал; CLI пишет «принято,
  исход неизвестен», код 0 и `pending: true`.

## Как это устроено сегодня (вход для CLI)

| Что | Откуда |
|---|---|
| Сессии, окна, хосты окон, снимки | `ccfzf --state` (`sessions[].window/windows`, `windowHosts`, `snapshots`) |
| Иерархия head → дети | `~/.ccfzf/heads/<id>.json`, `~/.ccfzf/children/<id>.json` (`lineage.mjs`) |
| Имя, статус busy/idle | `claude agents --json`, `~/.claude/sessions/<pid>.json` (`find.mjs`) — только живые сессии |
| Где стоит окно (монитор, зона, слот) | `~/.ccfzf/windows/<host>.json` (`find.mjs`) |
| Адрес менеджера | `http` в файле трекера (`spawn.mjs`) |
| Действия | `/claude-wt/focus` `{id}`, `/claude-wt/place` `{mode, ids}` / `{mode:"group", groups, selected}` (`parseArrangePayload`, `src/claude-layout-helpers.js`), `/claude-wt/snapshot-restore` `{id, sessionIds}`, `/claude-wt/session-new` |

## Команды

Шаг 1 (окна и картина):

```
claude-wt tree [--json]                  # сессии, окна, head/дети, снимки; помечает «свои»
claude-wt window focus <session>         # только поднять существующее окно
claude-wt window layout <head>           # раскладка своей группы head
claude-wt snapshot list [--json]         # снимки трекеров с http
claude-wt snapshot restore <id|last> [--sessions a,b]
```

`<session>` — sessionId, его префикс или имя. Имя разрешается по живым
сессиям (`claude agents --json`), а у закрытых — по `title` из `ccfzf --state`;
неоднозначное — отказ со списком кандидатов.

Шаги 2–6 (сессии, по одному переезду на шаг): `session find`, `session rename`,
`session close`, `head mark`/`head adopt`/`head lineage`, `session spawn`;
`session open` (открыть сессию, когда окна нет — дорога `session-open`, с
правилом «не повторять») — там же, отдельным шагом. На каждом шаге старый
`.mjs` в скилле зовёт CLI, его тесты в `~/.claude/skills/test/` проходят без
правок.

Коды выхода: 0 — сделано (или принято при `pending`), 1 — отказ с причиной (в
stderr и в `error` при `--json`), 2 — не найдено (сессия, окно, машина), 3 —
исход неизвестен (таймаут; повтор запрещён там, где он открыл бы второе окно —
правило `spawn.mjs`).

## Скилл `claude-wt-cli`

Команды с примерами; что агенту можно без спроса (Стас: `focus`, `layout`;
head: `snapshot restore` своих сессий — поднимает несколько окон разом, звать
по делу); только свои сессии; закрытие — только по подтверждению пользователя;
как читать коды выхода и `pending`.

## Проверка

- Юнит-тесты CLI на мок-сервере (`--url`) и подменённых каталогах; живой порт
  менеджера в тестах не трогать (правило `spawn.mjs`).
- Тесты windows11-manager на `raiseOnly`, `foreground` и `{ok:false}`; пикер
  ведёт себя как раньше (его ответы 2xx не читаются — убедиться прогоном).
- Вживую на машине с окнами: `tree --json` против пикера; `focus` своей сессии
  на другом виртуальном столе; `focus` сессии без окна — отказ, нового окна нет;
  `focus` чужой сессии — отказ; `layout` своей группы с двумя детьми;
  `snapshot restore` тестового снимка.
- Каждый шаг переезда сессий: тесты `~/.claude/skills/test/` и прежний сценарий
  на тестовом ребёнке (spawn → find → rename → close).
