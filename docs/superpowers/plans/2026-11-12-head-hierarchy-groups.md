# Группы раскладки с иерархией head — план работ (часть пикера)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** у каждой сессии с живыми прямыми детьми есть своя группа раскладки, в том числе у ребёнка, который сам стал head. `Ctrl+Win+F10` на сессии посередине раскладывает её собственную группу, на листе — группу его родителя.

**Architecture:** `place_order::group_ids` перестаёт пропускать строки с родителем. Группы идут **от самого глубокого head к корню**, при равной глубине — порядком пикера. Менеджер берёт первую группу, где есть `selected`, а без него — первую, где есть сессия активного окна (`pickGroup`, `windows11-manager/src/claude-wt/head-zones-helpers.js:294`). Сессия посередине входит в две группы: свою и родителя. Её собственная стоит раньше, и правило менеджера выбирает её само. Контракт `claude-place` не меняется, правок у менеджера нет.

**Tech Stack:** Rust (`src-tauri`, `cargo test`), фикстура JSON с JS-сторожем (`npm test`).

**Spec:** соседний репозиторий windows11-manager, `docs/superpowers/specs/2026-11-12-head-hierarchy-and-spawn-cwd-design.md`, раздел «Пикер: группы с иерархией». Предыдущая часть — план `docs/superpowers/plans/2026-11-11-group-tile-hotkey.md` (PR #57).

## Global Constraints

- **Контракт не менять:** `{"mode":"group","groups":[[head, child...], ...],"selected": id|null}`, тот же топик и маршрут.
- В группе: первый id — head, дальше его **прямые** живые дети на этой машине, в порядке пикера.
- Head без живых детей группы не образует.
- Правило родителя — прежнее (`parent_index`, общее с `nestByHead`). Циклы рвутся как в дереве: узел, чей предок оказался им самим, становится корнем.
- Отказ «подсвеченная строка не входит ни в одну группу» остаётся как есть.
- Ветка `feat/head-hierarchy-groups` поверх `feat/group-tile-hotkey` (PR #57 не смержен). PR — в `feat/group-tile-hotkey`, после мержа #57 перенацелить на `master`.
- Комментарии и тесты по-русски. Имён машин и домашних путей в репозиторий не класть.
- Выкатка — по правилам проекта, после пуша, `BRANCH=feat/head-hierarchy-groups`. Мерж и релиз — после того, как Стас посмотрит.

## Решения (приняты здесь)

1. **Слать все группы, а не одну нужную.** Одну нужную пикер знает, только когда окно открыто и строка выбрана. На скрытом пикере `selected` — `null`, и группу выбирает менеджер по активному окну, которое пикеру неизвестно. Порядок «глубокий head первым» даёт верный ответ в обоих случаях одним правилом, а менеджер его уже ждёт (комментарий у `pickGroup`).
2. **Глубина head** — число предков по `parent_index` после разрыва циклов. Корень — 0.
3. **Скрытый пикер, активно окно сессии посередине** — раскладывается её собственная группа, если у неё есть живые дети. Иначе своей группы у неё нет, и раскладывается группа родителя. Это следует из решения 1. Подтверждено Стасом 2026-11-12: «да, если у неё есть дети».
4. **Живость head по-прежнему не спрашивается.** Сессия посередине, сама закрытая, но с живыми детьми и окном здесь, свою группу получает. Подтверждено Стасом 2026-11-12.

## Review Focus

1. **Цепочка из трёх уровней** (h > x > x1 > x2). Каждая сессия посередине при выборе даёт свою группу, лист x2 — группу x1. Тест — Task 1, случай `chain` с `picks`.
2. **Сессия посередине без живых детей** (все её дети закрыты). Своей группы нет, она остаётся ребёнком в группе родителя. Тест — Task 1, случай `mid-without-live-children`.
3. **Две сессии посередине на одной глубине.** Группы идут порядком пикера, ни одна не теряется. Тест — Task 1, случай `nested` (x и y оба дети h, у x свои дети) и проверка числа групп.
4. **Цикл в записях** (правка руками). Группа не ходит по кругу: прежний случай `cycle` остаётся с прежним ожиданием.
5. **Выбранная строка, не входящая ни в одну группу.** Отказ прежний; тест уже есть, не трогается.

- [ ] **Step 1: Фикстура — новые ожидания (тест упадёт)**

`nested` (h > x, y; x > x1; все живые; порядок `h, x, y, x1`):
- `groups: [["x", "x1"], ["h", "x", "y"]]`;
- `picks`:
  - `x` → `["x", "x1"]`;
  - `x1` → `["x", "x1"]`;
  - `y` → `["h", "x", "y"]`;
  - `h` → `["h", "x", "y"]`.

`chain`: h > x > x1 > x2, все живые, `updated` убывает по цепочке (порядок `h, x, x1, x2`):
- `parents: {x: h, x1: x, x2: x1}`;
- `groups: [["x1", "x2"], ["x", "x1"], ["h", "x"]]`;
- `picks`:
  - `h` → `["h", "x"]`;
  - `x` → `["x", "x1"]`;
  - `x1` → `["x1", "x2"]`;
  - `x2` → `["x1", "x2"]`.

`mid-without-live-children`: h > x, x > x1, где x1 не живой:
- `parents: {x: h, x1: x}`;
- `groups: [["h", "x"]]`;
- `picks`: `x` → `["h", "x"]`.

Комментарий `nested` в `comment` фикстуры переписать: «у сессии посередине своя группа, и стоит она раньше группы родителя».

Остальные случаи (`basic`, `by-name`, `by-window-title`, `cycle`) — ожидания прежние, `picks` добавить там, где группа есть: `basic` `c1` → `["h", "c2", "c1"]`, `cycle` `b` → `["a", "b"]`.
