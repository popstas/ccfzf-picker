## Решено оставить как есть

- [ ] **`takeover`: `kill -HUP` без проверки успеха.**
  `frontend-src/open-strategy.js`, ветка `takeover`. Четыре команды склеены
  через `;`, а не `&&`, и `kill -0` возвращает ненулевой код и на ESRCH
  («процесса нет»), и на EPERM («процесс жив, не дотянуться»). Если `kill -HUP`
  не сработал вовсе, все три проверки читают это как «процесс ушёл», и
  `claude --resume` запускается — ровно тот случай с двумя процессами на одном
  транскрипте, который комментарий в этом же коде обещает не допустить.

  Решение владельца проекта (2026-08-05): **оставить как в плане.** Практически
  EPERM почти невозможен — процесс того же uid.

  Если когда-нибудь захочется закрыть: менять `;` на `&&` **нельзя** — тогда
  сессия, умершая между обновлением списка и кликом, даст ESRCH, цепочка
  оборвётся, и человек не получит ничего. Нужно различать два отказа:

  ```sh
  kill -HUP 42 || kill -0 42 2>/dev/null && { echo "…cannot signal 42" >&2; exit 1; }
  ```

  то есть отказываться только когда сигнал не прошёл **и** процесс всё ещё
  виден. Вторая дверь в ту же дыру: `Number(row.pid)` на нечисловом pid даёт
  литерал `NaN`, и все проверки снова читают «процесса нет». Закрывается
  проверкой `Number.isInteger(pid)` перед сборкой ветки. Править надо и план
  (Task 7, блок `takeover`), а не только файл.

## Мелочи

- [ ] **`--dump` в худшем случае стал дороже.** `running_sessions()` теперь
  зовёт `proc_tmux` на каждую живую сессию, а тот запускает `tmux display` с
  таймаутом 2 с. Замеры сегодня — 0.33 с на всё, но зависший tmux-сервер может
  добавить до 2 с на каждую живую сессию внутри tmux. `dump` делит эту функцию
  с `state`, а пикер на Windows ждёт именно `dump`.

- [ ] **Перенос reptyr проверен только с `tmux-server` в роли держателя pty.**
  В бою держателем будет `sshd: user@pts/N` — он от того же юзера, не root,
  так что `ptrace_scope=0` хватит. Но эмпирически с sshd и kitty не проверялось;
  Task 12 это и проверит.

- [ ] **`session-groups.js` кладёт `monitor: null` в каждую группу.** Поле
