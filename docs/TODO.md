## Найдено при выполнении задач 9–14

- [ ] **Два процесса на одном транскрипте теперь допускаются сознательно.**
  Живая сессия открывается через `resume`, то есть рядом с уже работающей
  копией. Решение владельца проекта (2026-08-05): открывать повторно лучше,
  чем убивать чужую работу, раз переносить нечем. Перехват остался за
  `caps.takeover`, по умолчанию выключенным.

  Чем это может аукнуться, никто не проверял: две копии claude пишут в один
  файл транскрипта. Если всплывёт порча истории — вот первое место, куда
  смотреть.

- [ ] **`confirm()` в ветке перехвата не проверен.**
  Диалог подтверждения рисует `window.confirm` в webview. С `caps.reptyr: false`
  эта ветка теперь основная для живых сессий, так что проверить надо в первую
  очередь: если WKWebView вернёт `false` молча, перехват просто не сработает, и
  без единого сообщения.

- [ ] **Список на маке и на Windows совпасть не могут.**
  Пикер на Windows берёт сессии из `state.slots` оконного трекера
  (оконный трекер из windows11-manager): там те, за кем закреплено окно
  терминала. На маке трекера нет, спек его сознательно выкинул.

  Решено (2026-08-05) показывать только `live` — `onlyLive: true` в конфиге.
  Это ближайшее по смыслу, но не то же самое: сессия с открытым окном на
  Windows может быть уже не `live` по мнению ccfzf (так было с `18ea`), а живых
  по ccfzf сейчас семь против пяти окон. Полного совпадения не будет без
  своего учёта открытых терминалов на удалённом хосте — а это возвращает в проект ровно
  то отслеживание окон, от которого уходили.

  Побочное: с `onlyLive` поиск ищет по семи строкам, а не по двум сотням.
  Старую сессию из пикера теперь не найти — только `onlyLive: false`.

- [ ] **Перенос держится на capability, выданных вручную.**
  `reptyr -T` работает только потому, что на `/usr/bin/reptyr` выданы
  `cap_sys_ptrace,cap_dac_read_search+ep` (см. архив скилла claude-wt).
  Обновление пакета `reptyr` их снимет — и пункт ^R начнёт отдавать команду,
  которая молча не работает. Проверять при обновлениях: `getcap /usr/bin/reptyr`.

- [ ] **tmux отпадает: перехватывает хоткеи, скролл и OSC.**

## Мелочи

- [ ] **`--dump` в худшем случае стал дороже.** `running_sessions()` теперь
  зовёт `proc_tmux` на каждую живую сессию, а тот запускает `tmux display` с
  таймаутом 2 с. Замеры — 0.3 с на всё, но зависший tmux-сервер может
  добавить до 2 с на каждую живую сессию внутри tmux. `dump` делит эту функцию
  с `state`, а пикер на Windows ждёт именно `dump`.

- [ ] **Перенос reptyr проверен только с `tmux-server` в роли держателя pty.**
  В бою держателем будет `sshd: <user>@pts/N` — он от того же юзера, не root,
  так что `ptrace_scope=0` хватит. Эмпирически с sshd и kitty так и не
  проверялось: Task 12 должна была это закрыть, но проверка требует рук.
