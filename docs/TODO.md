## Решено оставить как есть

- [ ] **`takeover`: `kill -HUP` без проверки успеха.**
  `frontend-src/open-strategy.js`, ветка `takeover`. Четыре команды склеены
  через `;`, а не `&&`, и `kill -0` возвращает ненулевой код и на ESRCH
  («процесса нет»), и на EPERM («процесс жив, не дотянуться»). Если `kill -HUP`
  не сработал вовсе, все три проверки читают это как «процесс ушёл», и
  `claude --resume` запускается — ровно тот случай с двумя процессами на одном
  транскрипте, который комментарий в этом же коде обещает не допустить.

  Решение владельца проекта (2026-08-05): **оставить как в плане.** Практически
  EPERM почти невозможен — процесс того же uid. С `caps.reptyr: true` ветка
  вдобавок стала недостижимой: перехват выбирается, только если reptyr выключен
  в конфиге.

  Если когда-нибудь захочется закрыть: менять `;` на `&&` **нельзя** — тогда
  сессия, умершая между обновлением списка и кликом, даст ESRCH, цепочка
  оборвётся, и человек не получит ничего. Нужно различать два отказа:

  ```sh
  kill -HUP 42 || kill -0 42 2>/dev/null && { echo "…cannot signal 42" >&2; exit 1; }
  ```

  то есть отказываться только когда сигнал не прошёл **и** процесс всё ещё
  виден. Вторая дверь в ту же дыру: `Number(row.pid)` на нечисловом pid даёт
  литерал `NaN`, и все проверки снова читают «процесса нет». Закрывается
  проверкой `Number.isInteger(pid)` перед сборкой ветки.

## Найдено при выполнении задач 9–14

- [ ] **Живая сессия без pid открывается через `resume`.**
  `chooseOpenStrategy` возвращает `resume`, когда `live`, но `pid` нулевой, —
  и тогда `claude --resume` поднимает **второй** процесс на том же
  транскрипте. Это ровно то, что ветка `takeover` существует предотвращать.
  Не теория: в ответе example-host от 2026-08-05 живых интерактивных сессий было 7,
  а pid знал ccfzf только у одной. Остальные шесть открылись бы вторым
  процессом.

  Чинить надо не в пикере: пикеру нечем отличить «процесса нет» от «pid не
  нашли». Либо `ccfzf --state` не должен звать сессию живой без pid, либо у
  строки нужен третий признак — «жива, но не опознана», — и для него отдельная
  ветка (отказ с объяснением, а не тихий resume).

- [ ] **`confirm()` в ветке перехвата не проверен.**
  Диалог подтверждения рисует `window.confirm` в webview. С `caps.reptyr: false`
  эта ветка теперь основная для живых сессий, так что проверить надо в первую
  очередь: если WKWebView вернёт `false` молча, перехват просто не сработает, и
  без единого сообщения.

- [ ] **Список на маке и на Windows — это разные списки.**
  Пикер на Windows берёт сессии из `state.slots` оконного трекера
  (`window-tracker/src/claude-wt/view.js`): там ровно те, за кем сейчас
  закреплено окно терминала, — пять штук. На маке трекера нет, спек его
  сознательно выкинул, и `ccfzf --state` отдаёт 200 последних транскриптов.
  Совпасть они не могут по построению: сессия с открытым окном на Windows может
  быть уже не `live` по мнению ccfzf, и наоборот.

  Решать надо, что означает «сессия, которую стоит показать» на маке. Варианты:
  оставить всё (сейчас), показывать только `live`, или завести на example-host свой
  учёт открытых терминалов — но последнее вернёт в проект то самое отслеживание
  окон, от которого уходили.

- [ ] **Живая сессия без tmux теперь всегда убивается перехватом.**
  Прямое следствие `caps.reptyr: false`. Ветка `attach` работает только у
  сессий внутри tmux, а их сейчас нет ни одной. Если запускать claude на example-host
  внутри tmux, перехват станет не нужен вовсе — и это, похоже, дешевле, чем
  чинить reptyr.

- [ ] **Сортировка и чекбоксы statusline не переживают перезапуск.**
  На Windows их помнил `config.yml` на стороне бэкенда. Здесь бэкенда нет, а
