  на маке не сделана (мак недоступен с конца октября 2026, решение Стаса
  14.11). windows11-manager с 22.11 ставит в слот и в файл трекера `unreadAt`
  (epoch-секунды) на `claude-session-unread` и снимает его на
  `claude-session-seen` вместе с `focusedAt = now`; пикер считает сессию
  непросмотренной, пока `unreadAt` новее и seen.json, и `focusedAt` окна.
  Маковскому трекеру — то же: поле в записи окна и в его отпечатке, обработка
  обеих просьб (MQTT `<base>/windows/claude-session-unread|seen`, у мака http
  нет). До того «Mark unread» по маковскому окну работает только местной
  отметкой, а `claude-wt session unread` маковскую машину пропускает (нет
  http-менеджера — код 1).

- [ ] **Выкатить на мак откат привязки окна по заголовку (macos-windows-manager#13).**
  Разобрано 22.11 («окно есть, привязки нет — пикер заводит вторую
  `ExpertizeMe-2`», снято 2026-08-22). Причина — кольцо дамп↔привязка в трекере
  мака: привязка живёт только в памяти по номеру окна и теряется на перезапуске
  трекера и гашении экрана, вернуть её можно только через индекс дампа, а
  сессия за `--limit` без привязанного окна из дампа выпадает. Правка смержена
  (#13, `Tracker::tick`: пустой индекс — откат на слот с тем же заголовком,
  побеждает больший `last_seen_ms`, зеркало `resolveSession` windows11-manager),
  сторож связки «окно держит сессию в дампе» — ccfzf#39. Осталось выкатить на
  мак, когда он вернётся, и проверить вживую. На Windows не воспроизводится.
  Тёзки по имени (имя мёртвой сессии выдаётся снова) — решение Стаса 22.11:
  оставить как есть.

  нужен. Встроенного перезапуска мёртвой панели нет:

  `merge_states` по-прежнему недостижим (id двух дампов не пересекаются).

- [ ] **Окно сессии на экране под курсором — маковская половина.** На Windows
  это уже работает: пикер прикладывает к просьбе `claude-session-open` точку
  курсора, менеджер ставит по ней новое окно. На маке терминал открывает сам
  пикер, чужое окно он двигать не умеет, а трекер (`macos-windows-manager`)
  просьб об открытии не принимает вовсе (`openSession: false`), идентичности
  экранов не знает (`Display` — голый прямоугольник, `CGDirectDisplayID` в
  `ax.rs` выбрасывается) и курсора не читает. То есть это не поле в теле, а
  новый протокол: топик вида «поставь окно сессии X, когда оно появится»,
  отложенная расстановка в `Tracker` рядом с той, что уже применяется на
  появление окна, плюс чтение курсора (`CGEvent::mouse_location`). Галка
  `openOnActiveDisplay` в пикере уже есть и на маке сегодня не делает ничего —
  об этом сказано в её подписи.
