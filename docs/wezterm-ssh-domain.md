# SSH-домен WezTerm с мультиплексором: оценка

Проба 22.11.2026 по пункту TODO «Оценить SSH-домен WezTerm с мультиплексором
вместо `wezterm start -- ssh …`». **Решение Стаса 22.11: пока не делаем** —
пункт в `docs/TODO.md` остаётся открытым, этот документ хранит результаты
исследования до возвращения к нему. Цепочку запуска (`claudeWt.launch*`,
`planWtLaunch`, терминал пикера) проба не трогала. Хосты ниже названы ролями:
**ноутбук** (Windows, где окна и трекер) и **ssh-хост** (Linux, где живут
сессии).

## Итог

**Главное обещание подтвердилось: claude переживает обрыв.** Процесс живёт под
`wezterm-mux-server` на ssh-хосте, окно подключается к той же панели заново, и
трекер привязывает окно к той же сессии. Это проверено по pid и времени старта
процесса до и после обрыва, а не по признаку «какой-то claude жив». Оговорка:
проверялся простаивающий claude. Ход, прерванный обрывом, — то, с чего пункт
TODO начинался, — на пробе не воспроизводили.

**Прямо перевести цепочку на домен нельзя**, и причина не в настройке:

1. Windows-клиент не может создать на Unix-сервере панель с командой
   ([wezterm#5474](https://github.com/wezterm/wezterm/issues/5474)). Обход есть,
   но запуск тогда делится на два шага.
2. При обрыве окно закрывается, само не переподключается. Переподключением
   должен заняться кто-то снаружи.
3. Цвет проекта (OSC 1337 `wt_profile`) теряется при каждом подключении.
4. Закрытие окна больше не завершает сессию.

**Рекомендация, если к пункту вернутся:** домен стоит доводить, если
принять четыре цены выше. Их закрывают три доработки в windows11-manager и
одна в Lua. Объём — новая схема запуска, а не правка шаблона, поэтому
начинать с чеклиста на глаз (ниже). Если после чеклиста домен покажется дорогим, кандидат — обёртка
`ssh … zellij attach`: zellij в связке уже есть. Её живучесть на пробе не
проверялась.

## Что проверено без глаз

Версия на обеих сторонах `20240203-110809-5046fc22`, совпадение знак в знак. На
ssh-хосте wezterm поставлен без root: `.deb` для Ubuntu 22.04 распакован
`dpkg-deb -x` в `~/opt/wezterm-20240203`, `ldd` для `wezterm` и
`wezterm-mux-server` чистый на Ubuntu 24.04. AppImage не брал: ему нужен FUSE.
`remote_wezterm_path` указывает на `wezterm`, а `wezterm-mux-server` тот ищет
рядом с собой.

| Проверка | Итог |
|---|---|
| `wezterm connect <домен> -- <prog>` с ноутбука | **не работает.** Сервер отвечает `reading Pdu from client: cannot deserialize Windows OS string on Unix`, окно закрывается. Причина в том, что `CommandBuilder` (`pty/src/cmdbuilder.rs`) сериализует argv, env и cwd как `OsString`, а у Windows это другой вариант. Issue закрыт как `not_planned`, без исправления. В `main` поля те же (`Vec<OsString>`); nightly не проверял |
| Обход: панель создаёт ssh-хост — `ssh <хост> wezterm cli --prefer-mux spawn --new-window --workspace <имя> -- <cmd>`, потом `wezterm connect --workspace <имя> <домен>` без PROG | работает |
| PROG при подключении к workspace, где панели уже есть | игнорируется: `have_panes_in_domain_and_ws` в `wezterm-gui/src/main.rs` подключается и выходит. Поэтому одна сессия — один workspace |
| Два окна, две сессии (`probe-a`, `probe-b`) | каждый процесс GUI показывает только свой workspace, трекер видит ровно два окна, каждое привязано к своей сессии |
| `wezterm connect` и живые окна Стаса | у `connect` всегда `always_new_process: true`, свой процесс. Все 13 живых `wezterm-gui.exe` пережили пробу. В логе одного из них в 19:15:03 есть `forcibly closed` на его локальном сокете, через ~11 с после старта пробного GUI. Связь не установлена: такие строки есть в логах живых GUI за много дней до пробы |
| Отдельный `ssh.exe` у клиента | его нет: у пробного GUI нет потомков, домен ходит встроенной ssh-библиотекой. Поэтому «kill ssh-клиента» из постановки заменён двумя обрывами — kill GUI на ноутбуке и kill `sshd`-потомка соединения на ssh-хосте |
| Заголовок окна для трекера | доезжает: `✳ <имя>` → в файле трекера `title: <имя>`, `app: wezterm-gui.exe`. `ccfzf --state` отдаёт сессии `window`, pid совпадает с процессом claude. После переподключения привязка та же |
| Иконка окна | менеджер записал её в файл трекера (`icon`, служба ставит `WM_SETICON`); видна ли она — п. 6 чеклиста. Профиль у такого окна умолчательный: менеджер его не запускал и проекта не знает |
| Обрыв со стороны клиента: GUI убит по PID | claude жив (тот же pid, то же время старта), `wezterm connect --workspace` возвращает ту же панель |
| Обрыв со стороны сервера: убит `sshd`/`wezterm cli proxy` этого соединения при живом GUI | claude жив. **Окно закрывается вместе с процессом GUI** (`detached domain`, `domain detached panes`) и само не переподключается. Окно пропадает и у трекера |
| Мягкое закрытие окна (`CloseMainWindow`, как крестик) | GUI выходит, **панель и claude живут дальше** |
| OSC 1337 `wt_profile`, напечатанный до подключения | **не виден:** в `gui-attached` и позже `get_user_vars().wt_profile == nil`. В `ClientPane` (`wezterm-client/src/pane/clientpane.rs`) переменные пусты при создании и заполняются только уведомлением `SetUserVar`. Начальной синхронизации нет |
| OSC 1337, напечатанный при подключённом GUI | доходит: `user-var-changed wt_profile=work-project` |
| Смерть `wezterm-mux-server` (приближение panic ssh-хоста) | все claude умирают вместе с pty, окна закрываются. Это не хуже, чем сейчас: восстановление то же, `claude --resume` |
| Окружение панели | наследуется от того, кто вызвал `wezterm cli spawn`: CLI отдаёт серверу своё env. Значит, `$SHELL -ic 'cd -- … && …'` нужен по-прежнему (правило про `chpwd` и `project=`). Новое: в панели появляются `TERM_PROGRAM=WezTerm`, `WEZTERM_PANE`, `WEZTERM_UNIX_SOCKET`; у ssh-сессий сейчас только `TERM` |
| Проброс агента (`ssh -A`) | в 20240203 его нет, `mux_enable_ssh_agent` есть только в `main`. Сейчас потери нет: агент на ноутбуке остановлен, у живых сессий `SSH_AUTH_SOCK` тоже пуст |
| Свежий `wezterm-mux-server --daemonize` | сам заводит панель с шеллом в workspace `default`. Её надо убирать, иначе подключение к `default` её покажет |
| Размер панели | после подключения сервер по-прежнему показывает `80x24`, хотя окно стоит в зоне. Похоже, окно ужимается до размера удалённой панели (комментарий в `async_run_terminal_gui` об этом и говорит). Нужны глаза |

Холодный путь целиком (`probe-session.cmd` при неподнятом mux-server) прогнан
один раз: сервер поднялся, панель создана, окно появилось у трекера.

Не проверено: «чёрная дыра» сети без RST (сон ноутбука, обрыв Wi-Fi). Тут
клиент ждёт keepalive, а не EOF, и сколько он висит до закрытия окна — неизвестно.
Обрыв iptables-ом по условию задачи не делали.

## Что нужно доделать, если переводить

- **Запуск в два шага** (из-за #5474). Сначала `ssh <хост> <скрипт spawn>`
  создаёт панель в workspace с именем сессии, затем `wezterm connect --workspace
  <имя> <домен>`. Правило «`;` в удалённой команде не ставить» остаётся в силе
  для первого шага, он идёт обычным ssh.
- **Сторож переподключения.** Окно закрылось, а панель жива (`wezterm cli list`
  на ssh-хосте) — значит, перезапустить `connect`. Это прямая замена
  `ssh-reconnect.js`. Геометрию окна после переподключения ставит демон, как
  после restore.
- **Цвет — не из переменной панели.** Кандидат: имя профиля в имени workspace,
  Lua красит окно по `window:active_workspace()` в `gui-attached` или в
  `window-config-reloaded`. Не проверено.
- **Закрытие сессии убивает панель явно** (`wezterm cli kill-pane`): крестик
  больше этого не делает. Иначе панели копятся на ssh-хосте, а claude в них
  продолжает работать.

## Как повторить пробу

На ssh-хосте:

- `~/opt/wezterm-probe/run-claude.sh` — OSC 1337, затем
  `$SHELL -ic 'cd -- "$1" && exec claude -n "$2"'`;
- `~/opt/wezterm-probe/spawn.sh <имя> [профиль]` — поднимает mux-server, если
  его нет, и создаёт панель в workspace `<имя>`.

Каталог сессий пробы — `~/tmp/wezterm-probe`.

На ноутбуке, в `%USERPROFILE%\wezterm-probe\`:

- `probe.lua` — надстройка над живым `.wezterm.lua` через `dofile`, живой
  конфиг не тронут. Добавляет `ssh_domains` и лог событий в `events.log`;
  `wezterm.log_info` в журнал GUI на Windows не попадает;
- `probe-connect.cmd` — `start "" wezterm-gui.exe --config-file probe.lua
  connect %*`;
- `probe-session.cmd <имя> [профиль]` — оба шага одной командой.

```lua
local wezterm = require 'wezterm'
local config = dofile(wezterm.home_dir .. '/.wezterm.lua')
config.ssh_domains = {
  {
    name = 'probe',
    remote_address = '<ssh-хост>',
    username = '<пользователь>',
    multiplexing = 'WezTerm',
    remote_wezterm_path = '<домашний каталог>/opt/wezterm-20240203/usr/bin/wezterm',
    assume_shell = 'Posix',
  },
}
return config
```

Механика проверки без глаз:

- запуск GUI идёт через `schtasks /ru <user> /it`: из ssh-сессии окно попало бы
  в session 0;
- убивать только по PID с `probe.lua` в командной строке;
- мягкое закрытие — тоже задачей в сессии 1: `taskkill` без `/F` из сессии 0
  отвечает «can only be terminated forcefully».

## Чеклист на глаз

Запуск из PowerShell на ноутбуке:

```
& "$env:USERPROFILE\wezterm-probe\probe-session.cmd" wezterm-probe-1 work-project
```

1. Окно открылось одно, без лишнего «Connecting…» и без второй вкладки.
2. Цвет: Material (work-project). Если цвет умолчательный (Solarized Dark) —
   OSC успел раньше подключения.
3. Размер: панель заполняет окно, справа и снизу нет полей 80×24. То же после
   того, как демон или автопостановщик переставит окно в зону.
4. Shift+Enter в claude переносит строку и не отправляет запрос. В панели
   теперь `TERM_PROGRAM=WezTerm`.
5. Ссылка в выводе claude (например, URL из ответа) кликается по Ctrl+клику.
6. Иконка окна в панели задач и в Alt+Tab.
7. Закрыть окно крестиком, затем снова
   `& "$env:USERPROFILE\wezterm-probe\probe-connect.cmd" --workspace wezterm-probe-1 probe`.
   Та же беседа, прокрутка на месте; цвет, скорее всего, умолчательный (п. 2).
8. Обрыв сети — **только когда ни у одной живой сессии не идёт ход**: Wi-Fi
   оборвёт и все обычные окна, у каждого свой `ssh.exe`, и их ходы пропадут.
   При открытом пробном окне отключить Wi-Fi на 30–60 с и включить. Как долго
   окно висит, закрывается ли само, что видно.
9. Убрать за собой — на ssh-хосте:
   `~/opt/wezterm-20240203/usr/bin/wezterm cli --prefer-mux list`, затем
   `kill-pane --pane-id N` для пробных панелей и для панели `~` в workspace
   `default`. Сам `wezterm-mux-server` без панелей не выходит — его снять по
   pid (`pgrep -f opt/wezterm-20240203/usr/bin/wezterm-mux-server`).
