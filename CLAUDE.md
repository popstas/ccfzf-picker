# ccfzf-picker

Пикер сессий claude-wt. Список берётся из `ccfzf --state` по ssh, окно и
хоткеи — Tauri 2. Начинать с [README.md](README.md) и
[docs/HANDOFF.md](docs/HANDOFF.md); здесь — только связи с соседями и статус
переноса на Windows.

## Место в связке claude-wt

Проект — один из **двух** пикеров одной и той же связки. Полное описание связки
в скилле `claude-wt` (`~/.claude/skills/claude-wt/`); ниже — то, что нужно
знать, правя этот репозиторий.

| Часть | Где | Что даёт этому проекту |
|---|---|---|
| Хуки агента | example-host, `~/.claude/hooks/` (тот же каталог виден и с Windows) | Пишут `<id>.state.json` на каждое событие агента |
| Агрегатор `ccfzf` | example-host, `/home/user/bin/ccfzf` | `ccfzf --state` — единственный источник списка для этого пикера. В репозитории лежит снимок `vendor/ccfzf`, правится оригинал на example-host |
| Демон и библиотека | `/home/user/projects/window-tracker`, `src/claude-wt/` | Этому пикеру не нужны, но это источник списка у соседнего |
| Пикер neighbor-picker | `/home/user/projects/neighbor-picker` | Соседний пикер: та же задача, другой источник и другая машина |
| Панель | хост панели | Этого пикера не касается |

**Два пикера не сойдутся в списках, и это решено.** Соседний строит список из
оконного трекера window-tracker — там сессия есть, пока у неё есть окно
Windows Terminal. Здесь список приходит из `ccfzf --state`, где сессия есть,
пока жив процесс. Договорённость: показывать только живые (`onlyLive: true` в
умолчаниях `frontend-src/config-shape.js`).

**Хоткеи не должны сталкиваться.** Соседний пикер сидит на `Super+F10`
(`picker.hotkey` в `config.example.yml` neighbor-picker), проектные хоткеи
window-tracker — на `Ctrl+F11` / `Ctrl+F12`. Умолчание здесь —
`Cmd+Shift+C`, то есть `Win+Shift+C` на Windows: `SUPER` — это Cmd на маке и
Win на Windows, одна запись даёт обе комбинации.

**Открытие сессии на Windows делается так же, как в соседнем пикере.** Форма
взята из `src/picker/session-open-helpers.js` в neighbor-picker: Windows Terminal,
внутри него ssh на example-host. `buildOpenCommand` в
`frontend-src/open-strategy.js` собирает
`[terminal.file, ...terminal.args, 'ssh', '-t', sshHost, remote]`, и с
`terminal.file: wt.exe` это ровно тот же вызов. Проверено на 2026-08-05:
одинарные кавычки внутри `remote` доходят до шелла на той стороне целыми.

Что при этом надо помнить (правила соседей, оплаченные их багами):

- **`;` в удалённой команде не ставить** — для Windows Terminal это разделитель
  панелей. Стратегия `takeover` в `open-strategy.js` склеивает команду через
  `; ` и на Windows развалится; она выключена (`caps.takeover: false`), но при
  включении это первое, что сломается.
- **`ssh host cmd` — неинтерактивный шелл.** zsh читает только `.zshenv`,
  `.zshrc` не читает. У ccfzf для этого есть своя форма (`$SHELL -ic "cd -- … &&
  …"`), у `claudeWt.launchNew` — своя (`exec $SHELL -ic '…' claude-wt '{cwd}'
  '{name}'` с позиционными аргументами). Здешняя форма — `inDir` в
  `frontend-src/open-strategy.js`: `exec $SHELL -ic 'cd -- <cwd> && <cmd>'`,
  та же, что у ccfzf. Через неё обязаны идти **все** удалённые запуски агента —
  и `resume`, и хвост `takeover`, и проектные хоткеи в `sessions.html`. Без неё
  не отрабатывает хук `chpwd`, который ставит `project=` в
  `OTEL_RESOURCE_ATTRIBUTES`, и агент пишет телеметрию без имени проекта.
  `cd` стоит **внутри** интерактивного шелла, после чтения rc: иначе rc, сам
  куда-то переходящий, увёл бы каталог обратно. Кавычки при этом навешиваются
  дважды (`q` внутри `q`) — разбирать будут два шелла подряд.
- **Профиль WT берётся по cwd**, а не один на всех: `claudeWt.projects` в
  `window-tracker.config.js`. Здесь профиль не зашит вовсе — `terminal.args`
  оставлен пустым.

## Статус переноса на Windows (2026-08-05)

Ветка `feat/tauri-macos`. Сборка и запуск на Windows работают, интерфейс
рисуется, список приезжает с example-host.

Что пришлось сделать, чтобы это стало правдой:

- `src-tauri/icons/icon.ico` — без него `tauri-build` не собирает Windows-ресурс
  и падает до компиляции. Собран из готовых PNG (32/128/256).
- Умолчание хоткея переехало с `T` на `C`: `Win+Shift+T` система держит за
  собой, `RegisterHotKey` отвечал «already registered», и приложение падало на
  старте.
- Отказ регистрации хоткея больше не фатален — пишет в stderr и не мешает
  запуску: окно всё это время поднимается из трея.
- `HOME` на Windows не выставлен; `load_config` и `seen.json` теперь знают про
  запасной `USERPROFILE`.
- `pbcopy` заменён платформенной константой — на Windows `clip`.

Не сделано и не проверено:

- **Открытие сессии на Windows глазами никто не видел.** Форма вызова проверена
  отдельно (кавычки доезжают), но полный путь «выбрать строку → открыть
  сессию» руками не прогонялся.
- **Windows-конфиг лежит вне репозитория** — `%USERPROFILE%\.config\ccfzf-picker\config.yaml`.
  Умолчания в `config-shape.js` остались macOS-ными (kitty), и без этого файла
  на Windows открывать сессию нечем.
- **Гашение по клику мимо окна сделано проще, чем у соседа.** Подробности и цена
  — ниже.
- Остальной список непроверенного руками — в [docs/HANDOFF.md](docs/HANDOFF.md).

## Гашение по клику мимо: чем отличается от neighbor-picker

Задача одна, реализации разные. Здесь (`src-tauri/src/main.rs`) — обработчик
вешается на само окно внутри `setup`, под ключом `hideOnBlur`. У соседа
(`/home/user/projects/neighbor-picker/src-tauri/src/main.rs`) — общий
`.on_window_event` на билдере с проверкой `window.label() == "sessions"`.

Обе идеи соседа, которых здесь не хватало, перенесены 2026-08-05:

1. **`hide_window` идемпотентна**: `picker-hidden` уходит, только если окно было
   видимым. Иначе Esc давал две посылки — сначала явное скрытие, потом потеря
   фокуса, которая заходит в тот же обработчик.
2. **Отметка `LastHidden`**: клик по иконке в трее сначала уводит фокус (окно
   гаснет по blur), и только потом до обработчика доходит отпускание кнопки —
   без отметки он видел скрытое окно и показывал его заново. Решение то же, что
   у соседа: `picker_toggle(visible, just_hidden)`, покрыт тестом
   `tray_click_hides_instead_of_reopening`.

`DEBOUNCE` в `toggle_picker` остался на своём месте — он про дребезг самой
кнопки и о гашении по blur по-прежнему не знает; `LastHidden` закрывает именно
это. Глазами на живом трее ни то, ни другое не проверялось.
