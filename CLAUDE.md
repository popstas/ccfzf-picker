# ccfzf-picker

Пикер сессий Claude Code на удалённой машине. Список берётся из `ccfzf --state`
по ssh, окно и хоткеи — Tauri 2. Начинать с [README.md](README.md).

## Сборка и тесты

```
npm test                      # фронтенд, node --test, без зависимостей
cd src-tauri && cargo test    # оболочка
```

`node --test test/` на этих версиях Node не работает — только `npm test`.

## Правила, за которые уже заплачено

- **`;` в удалённой команде не ставить** — для Windows Terminal это разделитель
  панелей, и команда развалится на панели вместо выполнения. Стратегия
  `takeover` в `frontend-src/open-strategy.js` склеивает команду через `; `; она
  выключена (`caps.takeover: false`), но при включении это первое, что сломается.

- **`ssh host cmd` — неинтерактивный шелл.** zsh читает только `.zshenv`,
  `.zshrc` не читает. Форма `inDir` в `frontend-src/open-strategy.js`:
  `exec $SHELL -ic 'cd -- <cwd> && <cmd>'`. Через неё обязаны идти **все**
  удалённые запуски агента — и `resume`, и хвост `takeover`, и проектные хоткеи
  в `sessions.html`. Без неё не отрабатывает хук `chpwd`, который ставит
  `project=` в `OTEL_RESOURCE_ATTRIBUTES`, и агент пишет телеметрию без имени
  проекта.

- **`cd` стоит внутри интерактивного шелла**, после чтения rc: иначе rc, сам
  куда-то переходящий, увёл бы каталог обратно. Кавычки при этом навешиваются
  дважды (`q` внутри `q`) — разбирать будут два шелла подряд.

- **Список не перерисовывается целиком.** Подача тикает раз в секунду; запись в
  DOM идёт через `syncList()` и `frontend-src/picker-list-sync.js`, которые
  правят только отличающиеся строки. `list.innerHTML = html` на каждый тик
  ронял скролл и гасил hover.

- **Про окна пикер не спрашивает никого — они приезжают в ответе агрегатора.**
  `ccfzf --state` читает у себя файл, который кладёт рядом оконный трекер с той
  машины, где сессии видны на экране, и добавляет каждой сессии поле `window`, а
  ответу — `windowHost` и `windowPid`. Своего http-клиента у пикера нет и не
  должно появиться: сервер на той стороне вешал демона через две-три минуты
  после старта (разбор — в репозитории соседа). Устаревший файл агрегатор
  отбрасывает сам, старше двух минут.

- **Передний план на Windows выдаётся, а не берётся.** Окно сессии поднимает
  демон оконного трекера, но `SetForegroundWindow` система разрешает только
  тому, кто передним планом уже владеет либо получил последнее событие ввода.
  Демон — ни то, ни другое: он просто слушает брокера. Право ему передаёт сам
  пикер, `allow_tracker_foreground` в `src-tauri/src/main.rs`, по `windowPid` из
  ответа агрегатора, и **до** публикации, пока нажатие ещё наше. Без грамоты
  трекер отчитается об успехе, а на экране мигнёт кнопка на таскбаре — отказ
  невидим с обеих сторон. По той же причине пикер гасится до публикации, а не
  после: гашение после отобрало бы у окна только что полученный фокус.

- **Поднимать ли окно, решает совпадение имён машин.** `windowHost` в конфиге
  против `windowHost` в ответе — `canFocus` в `frontend-src/session-windows.js`,
  вся проверка. На маке агрегатор рассказывает про окна Windows-машины: пометка
  ▣ там полезна, а ветка `focus` не включается — подъём окна на чужом экране
  ничего не дал бы человеку, а Enter лишился бы привычного открытия терминала.
  Пустое поле в конфиге значит «фокуса не бывает», и это умолчание.

- **Настроенный `mqtt` — условие выполнимости фокуса, а не второе решение.**
  Просьба о подъёме уходит единственным способом, публикацией в
  `<base>/windows/claude-focus`. Без брокера ветку `focus` предлагать нельзя:
  Enter молча не сработал бы, а это хуже, чем открыть терминал.

- **Имена машин в репозиторий не возвращать.** Хост берётся из
  `~/.config/ccfzf-picker/config.yaml`, умолчания у него нет.
  `test/no-private-data.test.js` это проверяет; список конкретных слов — в
  `data/private-patterns.txt`, каталог под `.gitignore`.

## Иконки и хоткеи

- `src-tauri/icons/icon.ico` обязателен: без него `tauri-build` не собирает
  Windows-ресурс и падает до компиляции.
- **Руками в `src-tauri/icons/` правится только `favicon.png`.** Остальные семь
  файлов — вывод `python3 scripts/make-icons.py`, и правка любого из них
  переживёт ровно до следующего запуска скрипта.
- Умолчание хоткея — `Cmd+Shift+C` (на Windows `Win+Shift+C`). `Win+Shift+T`
  система держит за собой: `RegisterHotKey` отвечает «already registered».
- Отказ регистрации хоткея не фатален — пишет в stderr и не мешает запуску:
  окно поднимается из трея.
- `HOME` на Windows не выставлен; `load_config` и `seen.json` знают про
  запасной `USERPROFILE`.
